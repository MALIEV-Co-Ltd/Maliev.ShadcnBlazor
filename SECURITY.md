# Security policy

## Supported versions

Security fixes are provided for the latest stable 1.x release. Older releases
may be asked to upgrade before a fix is issued.

## Reporting a vulnerability

Use GitHub private vulnerability reporting from the repository Security tab.
This keeps reports and proof-of-concept material confidential while the issue
is assessed and fixed.

Include the affected package version, environment, impact, reproduction steps,
and the smallest safe proof of concept available. Do not include credentials,
personal data, or data belonging to another party.

You should receive an acknowledgement within five business days. Valid reports
will be triaged, remediated, and disclosed on a timeline appropriate to their
severity and exploitability. Please allow time for a coordinated release before
sharing details publicly.

For usage questions and ordinary defects, follow [SUPPORT.md](SUPPORT.md).
