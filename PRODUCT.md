# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Blazor developers evaluating, learning, and integrating `Maliev.ShadcnBlazor`, plus maintainers extending the public component library safely.

## Product Purpose

`Maliev.ShadcnBlazor` provides reusable, accessible Shadcn-style components for Blazor. The public repository must let developers inspect every component interactively, understand its API and composition, copy a working Razor example, and install the NuGet package without depending on a private application.

## Positioning

The library pairs familiar Shadcn composition and visual language with native Blazor APIs, deterministic component evidence, and a public interactive documentation site generated from the same reviewed component catalog.

## Operating Context

Developers browse the GitHub Pages documentation, compare interactive states, copy Razor examples, install the NuGet package, and validate changes through unit, contract, accessibility, visual, and real-browser tests before release.

## Capabilities and Constraints

- The package and documentation remain independently consumable from the public repository.
- The component catalog is the authoritative source for component names, categories, status, API ownership, and evidence.
- Documentation routes must work locally and under the repository-scoped GitHub Pages base path.
- Existing public component APIs and example behavior remain unchanged unless a separately reviewed component change requires it.
- The site supports light and dark themes, LTR and RTL direction, reduced motion, forced colors, keyboard navigation, zoom, and responsive layouts.
- Public files must not contain credentials, customer data, private URLs, private product dependencies, or private application identifiers.

## Brand Commitments

- Product name: `Maliev.ShadcnBlazor`.
- Documentation information architecture follows the familiar Shadcn documentation pattern while retaining its own product identity and Blazor-specific content.
- Copy is direct, technical, and evidence-backed.

## Evidence on Hand

- Sixty-four complete component dossiers generated from the checked-in catalog.
- Interactive Razor examples, API descriptors, accessibility notes, evidence matrices, and browser-tested visual fixtures.
- Public CI, GitHub Pages, visual-proof, security, and NuGet release workflows.

## Product Principles

- Demonstrate before asking developers to install.
- Keep consumption guidance adjacent to the rendered component.
- Preserve native semantics and keyboard behavior.
- Make public boundaries explicit and mechanically verifiable.
- Prefer deterministic evidence over undocumented visual claims.

## Accessibility & Inclusion

Documentation and components must remain operable with keyboard and assistive technology, readable at 200% zoom, usable in forced colors, respectful of reduced motion, and correct in both LTR and RTL layouts.
